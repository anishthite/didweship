Summary

Goal
Count connected TikTok users’ public videos as an optional social shipping signal.
Source
POST https://open.tiktokapis.com/v2/video/list/ with scopes user.info.basic,video.list.
Refresh
GitHub Action refreshes a bundled JSON cache; Vercel never receives TikTok credentials.
Surface
Optional channels.tiktok panel and github AND (x OR tiktok) combined streak.
Schema
Add optional tiktokLogin and slug-keyed tiktok-days-by-slug.json.
Mobile
Stack panels on small screens; use up to three columns at large widths.
Open Qs
1 (Q-001).

API contract

POST /v2/video/list/?fields=id,create_time
Authorization: Bearer <connected-user-access-token>
Content-Type: application/json

{ "max_count": 20, "cursor"?: number }

{ data: { videos: [{ id: string, create_time: number }], cursor?: number, has_more?: boolean } }

Algorithm

  1. Read TikTok-enabled roster entries and their mapped refresh tokens from GitHub Actions secrets.
  2. Refresh each connected user’s access token, then call /v2/user/info/ and require its open_id to match the configured slug.
  3. Page video/list, bucket create_time through NERV_TZ, and replace only the overlapping recent days.
  4. Atomically write tiktok-days-by-slug.json; commit it only when changed; trigger the existing deploy hook.
  5. Render TikTok when its cache is valid; hide offline social panels; treat a day as shipped when GitHub and either live social source have activity.

Decisions

IDChoice · Rationale
D-001Use the official Display API. It lists public videos only after account consent and avoids profile scraping.
D-002Keep TikTok optional and cache-backed. Missing approval, credentials, or data must not break GitHub/X pages.
D-003Start with maintainer-provisioned connected accounts in Actions secrets. The existing file-backed app has no token store for self-serve OAuth.
D-004Validate open_id before attribution. A token must never write videos under another roster slug.
D-005Use github AND (x OR tiktok). TikTok satisfies the social half without turning social-only days into ships.

Tradeoffs

IDPicked over Rejected · Reason
T-001Connected-account API over public-profile scraping. The API is authorized and stable; scraping is not.
T-002Secret-provisioned tokens over an in-app OAuth callback. The former adds no database or new runtime auth surface.

Open questions

Q-001 · Which TikTok accounts should authorize the app? Assumed: only existing tracked users. Arbitrary self-serve connections require OAuth callback and server-side token storage.

Assumptions

  • A-001 · The TikTok app is approved for user.info.basic and video.list; if not, the refresh workflow remains offline.
  • A-002 · The refresh-token rotation policy can be handled without silently losing the next refresh; if not, add a secure token-store path before enabling the schedule.

Reversibility

R-001 · medium. Remove the TikTok cache, reader, workflow, and snapshot/UI branches; GitHub+X behavior remains intact.

Followups

  • L-001 · Add Login Kit callback and encrypted token storage only when users must connect TikTok from /join.
